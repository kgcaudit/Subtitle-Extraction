# subex 웹 — 브라우저에서 영상 자막 추출

영상 파일을 고르면 그 안의 자막을 **SRT 파일로** 뽑습니다. 자막이 그림으로 들어 있으면
브라우저 안에서 글자로 읽어 냅니다.

**영상은 이 기기 밖으로 나가지 않습니다.** 서버로 올리지 않고 브라우저 안에서만 처리합니다.
설치할 것도 없고, 안드로이드·아이폰·PC·맥 어디서든 브라우저만 있으면 됩니다.

## 쓰는 법

```bash
cd web
npm install && npm run vendor   # 문자 인식 엔진을 vendor/ 로 복사 (한 번만)
npm run serve                   # http://127.0.0.1:8080
```

배포는 이 폴더를 정적 파일 그대로 올리면 끝입니다(사내 웹서버, 파일 공유, GitHub Pages 등).
**서버에서 도는 프로그램이 없습니다.**

`npm run vendor` 를 하면 인식 엔진과 언어 자료가 `vendor/` 에 들어가서 **바깥 인터넷이
막힌 사내망에서도** 그대로 동작합니다. 하지 않으면 공개 배포망에서 받아 옵니다.

## 지원 범위

| 영상 안의 자막 | 처리 | 결과 |
|---|---|---|
| **SubRip** 글자 자막 | 바로 변환 | ✅ 즉시 |
| **ASS/SSA** 글자 자막 | 스타일 태그 제거 후 변환 | ✅ 즉시 |
| **PGS** 그림 자막 (블루레이) | 그림 복원 → 문자 인식 | ✅ |
| **VobSub** 그림 자막 (DVD) | 그림 복원 → 문자 인식 | ✅ |
| **MP4 글자 자막** (tx3g/mov_text) | 바로 변환 | ✅ 즉시 |
| MP4 안의 WebVTT (wvtt) | 바로 변환 | ✅ 즉시 |
| DVB 자막 (방송) | — | ❌ 미지원 (목록에는 표시) |
| 화면에 새겨진 자막 (번인) | — | ❌ 범위 밖 |

컨테이너는 **MKV · WebM · MP4 · MOV** 를 읽습니다. 확장자가 아니라 파일 앞머리를 보고
가리므로 이름이 엉뚱해도 됩니다. 자막만 든 **.sup** 파일도 바로 넣을 수 있습니다.

## 얼마나 걸리나 (실측)

676메가바이트 영상(26분, 그림 자막 400줄)을 실제 크로미움에서 잰 값입니다.

| 단계 | 측정값 |
|---|---|
| 자막 트랙 목록 보기 | **5밀리초** (파일 앞 1메가바이트만 읽음) |
| 676메가바이트 훑어 자막 꺼내기 | **3.3초** (초당 약 205메가바이트) |
| 문자 인식 — 인식기 4개 | **장당 42밀리초** |
| 문자 인식 — 인식기 1개 | 장당 114밀리초 |
| 인식 엔진 준비 | 423밀리초 |

2시간 영화(자막 1,500줄) 기준 추정:

| 영상 크기 | 훑기 | 문자 인식 | 합계 |
|---|---|---|---|
| 1기가바이트 | 5초 | 63초 | **약 1분** |
| 5기가바이트 | 25초 | 63초 | **약 1분 30초** |
| 20기가바이트 | 100초 | 63초 | **약 3분** |
| *글자 자막* | 5~100초 | 없음 | **수 초~1분대** |

PC 브라우저 기준이며, 휴대폰은 2~3배 정도 더 걸립니다.
676메가바이트·26분·자막 400줄짜리를 실제로 끝까지 돌리면 **약 31초**입니다.

## 인식 정확도 — 언어 설정이 크게 좌우합니다

한글 자막 400줄로 실측한 값입니다.

| 인식 언어 | 한글만 있는 자막 | 한·영 섞인 자막 |
|---|---|---|
| 한국어만 | **98.0%** | 39% ❌ 영문이 깨집니다 |
| 한국어 + 영어 | 89.7% | **100%** |

어느 한쪽이 항상 낫지 않습니다. 그래서 기본값은 **자동**입니다.

자동은 앞부분 12장을 '한국어+영어'로 읽어 보고, **거기서 나온 영문 낱말을
인식기가 얼마나 확신하는지**를 봅니다. 진짜 영어면 확신하고(실측 95), 한글을
영문으로 잘못 읽은 것이면 확신하지 못합니다(실측 12). 그 차이로 가릅니다.

> 처음에는 두 설정의 전체 신뢰도를 견주려 했는데, 400장에서 89.8 대 89.5 로
> 뒤집혀 못 쓸 방법이었습니다. 지금 방식으로 바꾸니 같은 영상에서
> **89.7% → 98.0%** 가 됐습니다.

글자가 작아 잘 안 읽히면 '확대 배율'을 3~4배로 올려 보세요.

## 어떻게 검증했나

이 저장소의 **파이썬판이 정답지**입니다. 실제 영상으로 검증을 끝낸 구현이라,
웹판이 같은 입력에서 같은 답을 내는지를 기준으로 삼았습니다.

```bash
npm test
```

21개 시험이 있고, 대부분 **파이썬판이 낸 답과 맞춰 봅니다**.

| 시험 | 내용 |
|---|---|
| SRT 규칙 대조 | 까다로운 11가지 경우에서 파이썬판과 글자 단위로 같은지 |
| PGS 그림 해독 | 파이썬판이 해독한 그림과 **픽셀 단위로** 같은지 (.sup 파일 / MKV 안 둘 다) |
| VobSub 그림 해독 | 위와 같음 |
| MKV 글자 자막 | SubRip 이 그대로 읽히는지 |
| MP4 자막 트랙 | 트랙·언어를 찾아내고, SRT 와 시각이 파이썬판과 **밀리초까지** 같은지 |
| 파일 종류 가리기 | 앞머리만 보고 MKV·MP4·.sup 을 구분하고, 모르는 형식은 이유를 알려 주는지 |
| 자막 없는 영상 | 빈 목록과 안내 문구가 나오는지 |
| 실제 자막에 가까운 PGS | 안티에일리어싱(수십 가지 색)과 두 줄을 각각 다른 객체로 얹은 경우도 픽셀 단위로 같은지 |
| 자동 언어 선택 | 한글 전용 자막에서는 '한국어만', 한·영 혼합에서는 '한국어+영어'를 고르는지 |
| **브라우저 전체 흐름** | 진짜 크로미움에서 MKV·MP4·.sup 을 넣고 끝까지 돌려, 만들어진 SRT 가 파이썬판 결과와 **바이트 단위로 같은지** |

마지막 시험이 핵심입니다. 자막을 꺼내고, 그림을 해독하고, 글자를 읽고, 다듬어
SRT 로 만드는 전 과정을 한 번에 확인합니다.

### 실제 영상으로 검증하기

가진 영상을 넣으면 웹판을 돌려 보고, 이 컴퓨터에 파이썬판이 있으면 **자동으로
대조까지** 해 줍니다.

```bash
node tools/verify.js /경로/영화.mkv            # 웹판 실행 + 파이썬판 대조
node tools/verify.js 영화.mkv --dump 5         # 해독한 그림도 5장 저장해 눈으로 확인
node tools/verify.js 영화.mkv --lang kor       # 인식 언어를 직접 지정
node tools/verify.js 영화.mkv --no-python      # 대조 없이 웹판만
```

내놓는 것: 트랙 목록, 단계별 걸린 시간, SRT 파일, 그리고 파이썬판과의
**시각 일치 여부**와 **글자 일치율**, 다른 곳 다섯 군데까지.

시각이 다르면 자막을 꺼내는 쪽 문제이고, 글자만 다르면 문자 인식 차이입니다.
`--dump` 로 저장되는 그림을 보면 인식기가 무엇을 보고 읽었는지 알 수 있습니다.

기준 자료를 다시 만들려면:

```bash
python3 ../tests/make_web_fixtures.py     # 그림·영상·SRT 정답지
python3 ../tests/make_parity_golden.py    # SRT 규칙 정답지
```

## 구조

```
web/
├── index.html · styles.css        화면 (반응형, 360픽셀부터)
├── src/
│   ├── reader.js       파일을 조각내어 읽기 (필요한 구간만)
│   ├── container.js    파일 종류를 가려 알맞은 해석기로
│   ├── mkv.js          MKV/WebM 해석 — 자막 트랙만 골라 꺼낸다
│   ├── mp4.js          MP4/MOV 해석 — 표(stbl)를 엮어 자막 조각 위치를 찾는다
│   ├── pgs.js          PGS 그림 해독 (세그먼트 + 런렝스)
│   ├── vobsub.js       VobSub 그림 해독 (제어 시퀀스 + 2비트 런렝스)
│   ├── extract.js      위 셋을 엮어 '시각 + 내용' 으로
│   ├── bitmapPrep.js   문자 인식 전처리 (흰 바탕 검은 글자로)
│   ├── ocr.js          문자 인식 (tesseract.js, 여러 개 병렬)
│   ├── postprocess.js  다듬기 (빈 줄·겹침·중복)
│   ├── srt.js          SRT 읽기/쓰기
│   └── app.js          화면 동작
├── tools/              개발 서버, 인식 엔진 복사, 실제 영상 검증(verify.js)
└── test/               위 검증들
```

## 아직 안 된 것

- **조각난 MP4(fragmented)** — 스트리밍용으로 만든 MP4 입니다. 읽으려 하면
  그렇다고 알려 줍니다.
- **DVB 자막(방송)** — 목록에는 보이지만 해독기가 없습니다.
- **화면에 새겨진 자막(번인)** — 자막 트랙이 아니라 영상 그림의 일부라 범위 밖입니다.
- 문자 인식은 한국어+영어로 맞춰 두었습니다. 다른 언어는 `vendor.js` 의 언어 목록과
  `ocr.js` 의 기본값을 바꾸면 됩니다.
