# subex 안드로이드 앱

폰에 있는 영상에서 자막을 뽑아 SRT 파일로 저장합니다. 자막이 그림으로 들어 있으면
문자 인식을 거쳐 글자로 만듭니다. **인터넷을 쓰지 않고 폰 안에서만** 처리합니다.

## 왜 파이썬 코드를 옮기지 않았나

파이썬판은 ffmpeg 과 Tesseract 에 기대고 있는데, 안드로이드에서 ffmpeg 을 쓰게 해 주던
FFmpegKit 이 2025년 1월 은퇴하면서 직접 빌드하지 않고는 쓸 수 없게 됐습니다.

대신 구글의 **Media3** 가 필요한 걸 전부 갖고 있습니다.

| 파이썬판에서 직접 만든 것 | 안드로이드에서 쓰는 것 |
|---|---|
| ffmpeg 으로 컨테이너 해체 | Media3 `MediaExtractorCompat` |
| PGS(.sup) 해독기 직접 구현 | Media3 `PgsParser` |
| VobSub SPU 해독기 직접 구현 | Media3 `VobsubParser` |
| (미지원) | Media3 `DvbParser` — 방송 자막까지 됩니다 |
| Tesseract | ML Kit 한국어 문자 인식 (모델 약 4MB 내장) |

직접 만든 해독기 두 개가 통째로 필요 없어졌고, 설치 파일도 작아집니다.

## 구조

```
android/
├── core/     순수 코틀린. 안드로이드 의존성이 없어서 기기 없이 테스트된다.
│             Cue · Srt · Postprocess · SubtitleTrackInfo · TextLayout
└── app/      안드로이드. Media3 로 자막을 꺼내고 ML Kit 으로 읽는다.
              SubtitleReader · BitmapPrep · KoreanOcr · ExtractionEngine · 화면
```

`core` 를 따로 뗀 이유가 있습니다. **파이썬판과 결과가 같은지 대조하는 규칙**이
여기 들어 있는데, 이걸 기기나 안드로이드 SDK 없이 검증할 수 있어야 하기 때문입니다.

```bash
cd android/core && gradle test     # 안드로이드 SDK 없이 돌아갑니다
```

## 빌드

Android Studio(Ladybug 이상)에서 `android/` 폴더를 엽니다. 나머지는 자동입니다.

명령줄로 하려면:

```bash
cd android
./gradlew :app:assembleDebug
# 결과: app/build/outputs/apk/debug/app-debug.apk
```

빌드하려면 `dl.google.com` 과 `maven.google.com` 에 접근할 수 있어야 합니다
(안드로이드 SDK 와 구글 라이브러리가 거기 있습니다).

## 지금까지 검증된 것과 안 된 것

정직하게 구분해 둡니다.

**실제로 돌려서 확인한 것 (27개 테스트 통과)**

- SRT 읽기·쓰기, 시간 표기, 까다로운 입력 처리
- 자막 다듬기 규칙 — 빈 줄 제거, 최소 길이, 겹침 정리, 중복 병합
- 출력 파일 이름 규칙
- 문자 인식 결과의 줄 세우기 (조각난 인식 결과를 원래 줄로 복원)
- **파이썬판과의 결과 대조** — 까다로운 11가지 경우에서 두 구현의 출력이 글자 단위로 일치

**아직 확인 못 한 것**

- 앱 모듈 컴파일 — 작업 환경에서 `dl.google.com` 이 막혀 있어 안드로이드 SDK 를
  받지 못했습니다. 처음 빌드할 때 라이브러리 버전 정도는 손봐야 할 수 있습니다.
- 실제 기기에서의 동작, ML Kit 한국어 정확도, 처리 속도

## 폰에서 정확도 확인하기 (0단계)

이 앱을 만든 목적 중 절반은 **ML Kit 한국어 인식이 자막에서 쓸 만한지 재 보는 것**입니다.
파이썬판(Tesseract)이 합성 자막에서 문자 단위 98% 였으니 그게 비교 기준입니다.

1. 자막이 그림으로 들어간 영상(블루레이 립 MKV 등) 하나를 폰에 옮깁니다
2. 같은 영상을 PC 의 파이썬판으로 돌려 SRT 를 만듭니다 — 이게 **정답지**입니다
   ```bash
   subex movie.mkv --lang kor
   ```
3. 앱으로 같은 영상, 같은 트랙을 추출해 SRT 를 저장합니다
4. 두 SRT 를 비교합니다
   ```bash
   diff movie.kor.srt movie.kor.android.srt
   ```

시각(타임코드)이 어긋나면 자막을 꺼내는 쪽 문제이고, 글자만 다르면 문자 인식 차이입니다.
둘을 나눠 봐야 어디를 고칠지 정해집니다.

## 안 되는 것

- **화면에 박힌 자막(번인)** — 자막 트랙이 아니라 영상 그림의 일부라 범위 밖입니다
- 자막 없이 음성만 있는 영상 — 음성 인식이 필요한 다른 작업입니다
- 암호화된 스트림

## 권한과 개인정보

권한 선언이 하나도 없습니다. 사용자가 직접 고른 영상만 읽고, 사용자가 직접 고른
폴더에만 씁니다. 인터넷을 쓰지 않으므로 영상이 기기 밖으로 나가지 않습니다.
